# Addons

Addons add cluster-specific widgets to the Capsule pages without changing or rebuilding this
plugin. Typical uses:

- A row of "platform feature" icons on a namespace. Each icon shows whether a label is set,
  and a click sets or removes the label after a confirmation.
- An expiry date on each tenant, read from a label, that turns orange shortly before the date
  and red after it.
- Custom JavaScript that renders anything else, with access to the page's object and to the
  Kubernetes API through `capsule-proxy`.

An addon is a directory with a `manifest.json` (and, optionally, JavaScript modules and SVG
icons). You mount it into the plugin pod from any volume: a ConfigMap, a PVC, or an OCI image
volume.

## How it works

```
/usr/share/nginx/html/addons/index.json             generated by the Helm chart
/usr/share/nginx/html/addons/<name>/manifest.json   from the addon's volume
/usr/share/nginx/html/addons/<name>/…               optional .js modules, .svg icons
```

The console serves the plugin's files at `/api/plugins/console-plugin-capsule/`. When the
plugin loads, it reads `addons/index.json` from there, then each listed addon's
`manifest.json`. Invalid widgets are skipped, with a warning in the browser console
(`[console-plugin-capsule addons] …`). If one widget fails at runtime, only that widget shows
a warning icon; the rest of the page keeps working.

The plugin loads addons once per browser session. After you change an addon, reload the
console tab. The nginx config sets `Cache-Control: no-cache` for `addons/`.

## Installing an addon

1. Put the files in a volume source in the plugin's namespace, for example a ConfigMap:

   ```bash
   oc create configmap capsule-addon-platform-features -n console-plugin-capsule \
     --from-file=examples/addons/platform-features
   ```

2. List it in the chart values:

   ```yaml
   plugin:
     addons:
       - name: platform-features          # directory name below addons/
         volume:                          # any Kubernetes volume source
           configMap:
             name: capsule-addon-platform-features
       - name: custom-widgets
         volume:
           image:                         # OCI image volume (ImageVolume feature gate)
             reference: quay.io/example/capsule-addon-custom:1.0.0
             pullPolicy: IfNotPresent
   ```

   Names must be lowercase letters, digits and `-`, at most 57 characters.

3. Run `helm upgrade`. The pods roll automatically when the addon list changes. Later edits
   to a ConfigMap reach the running pods within about a minute, with no restart.

## Manifest reference

```json
{
  "apiVersion": "console-plugin-capsule/addons/v1",
  "widgets": [ { "type": "…", "id": "…", "slot": "…", … } ]
}
```

These fields are common to all widgets:

| Field | Description |
| --- | --- |
| `type` | `labelToggle`, `labelValue` or `module`. |
| `id` | Unique within the addon. |
| `slot` | Where the widget is shown: `namespace.detail` (the *Extensions* section of the tenant namespace page) or `tenant.row` (the *Extensions* column of the Tenants table, icons only). |
| `title` | Optional display name. |
| `icon` | `pf:<name>` for a built-in PatternFly icon (see [icons](#icons)), or a relative path to an image in the addon directory, such as `icons/backup.svg`. |
| `iconMode` | How image-file icons are drawn, see [icons](#icons). `"image"` (default) or `"mask"`. |

A **text** field can be a string, or a map from language to string. The plugin picks the
console's language, then the base language, then `en`:
`{"en": "Backup", "de": "Sicherung"}`. Most text fields accept placeholders: `{{name}}` (the
object's name), `{{title}}`, and, for `labelValue`, `{{value}}`, `{{raw}}` and `{{days}}`.

### `labelToggle`

An icon that shows whether a label is set. A click switches the label after a confirmation.

| Field | Default | Description |
| --- | --- | --- |
| `key` | – | Label key. |
| `match` | `"value"` | `"value"`: the toggle is on when the label has exactly `onValue`. `"exists"`: the toggle is on whenever the label is present, whatever its value (including `foo=`). |
| `onValue` | `"true"`, or `""` with `match: "exists"` | The value written when switched on. With `match: "value"`, it is also the value that counts as on. |
| `offValue` | – | The value to write when switched off. If you omit it, the plugin removes the label. You can't combine it with `match: "exists"`, because the label would still exist. |
| `icon` | – | One icon for both states, or `{ "on": …, "off": … }` for a different icon per state. If one state is missing, that state uses the other state's icon. |
| `readOnly` | `false` | Display only: the icon is never clickable. Use this for labels that automation or another team manages. |
| `text.on` / `text.off` | – | `{ "alt": …, "tooltip": … }` for each state. `alt` is the accessible name (screen readers, image `alt`). `tooltip` is shown on hover and keyboard focus. |
| `text.readOnly` | – | Added to the tooltip of read-only toggles, for example the reason or who to contact. |
| `text.noPermission` | generic message | Added to the tooltip when the user may not change the object. |
| `confirm` | generic prompt | `{ "enable": …, "disable": … }` confirmation texts, or `false` to switch without asking. |

**Who can switch a toggle:** the user needs `patch` permission on the object. For a namespace,
that's normally the tenant's owners and members with edit rights in that namespace. For a
tenant, it's whoever may patch the Tenant. The plugin checks this with a
`SelfSubjectAccessReview` through `capsule-proxy`, using the user's own token. Until the check
succeeds, the toggle stays disabled. A failed check also leaves it disabled. The API server
still enforces RBAC, and Capsule's webhooks (for example forbidden labels) still apply on the
actual patch. If a webhook rejects the patch, the dialog shows the error.

The on and off states differ in more than colour. The namespace page shows *On*/*Off* text,
and the button sets `aria-pressed`. With a single icon, the off icon is also dimmed and struck
through. With a dedicated `off` icon, the icon itself shows the state, so the plugin doesn't
add that decoration.

### `labelValue`

Read-only icon and text taken from a label or annotation, optionally parsed as a date.

| Field | Default | Description |
| --- | --- | --- |
| `key` | – | Label or annotation key. |
| `source` | `"label"` | `"label"` or `"annotation"`. |
| `text` | `"<title>: {{value}}"` | Text template. |
| `alt`, `tooltip` | – | Accessible name and tooltip (templates). |
| `emptyText` | – | Shown when the key is missing. If you omit it, the widget is hidden. |
| `format` | – | `{ "type": "date", "input": …, "display": …, "timezone": … }`, see below. |
| `warnDays` | – | For dates: show a warning this many days before the date. The widget always shows danger once the date has passed. |

**Date formats:**

- `input` (default `YYYY-MM-DD`): how to parse the value.
  - A token pattern built from `YYYY`, `MM`, `DD`, `HH`, `mm` and `ss`; every other character
    is a literal. For example `YYYYMMDD`, `DD.MM.YYYY` or `YYYY-MM-DD_HH-mm`. Label values
    can't contain `:` or spaces, so pick a pattern without them.
  - `"unix"`: seconds since the epoch.
  - `"iso"`: RFC 3339, such as `2026-12-31T23:59:00Z`. This only works in annotations.
- `display` (default `{"dateStyle": "medium"}`): how to show the date.
  - A token pattern, such as `"DD.MM.YYYY"`.
  - An [`Intl.DateTimeFormat` options](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat/DateTimeFormat#options)
    object, such as `{"dateStyle": "long"}` or
    `{"year": "numeric", "month": "short", "day": "2-digit"}`. This follows the console
    user's language.
  - `"relative"`, for output such as "in 12 days" or "yesterday".
- `timezone` (default `"UTC"`): `"UTC"` or `"local"` (the browser's time zone). The plugin
  uses it to parse values without an explicit offset, to display the date, and to count days.

If a value doesn't match `input`, the widget shows the raw value with a warning icon. The
tooltip names the expected format.

### `module`

Custom JavaScript, loaded with the browser's native `import()` from the addon directory.

| Field | Default | Description |
| --- | --- | --- |
| `module` | – | Path of an ES module, relative to the addon directory. |
| `export` | `"default"` | Export to call. |
| `config` | – | Any JSON. The module receives it as `host.widget.config`. |

The export is a factory. The plugin calls it once with a host object, and it returns a React
component (or a promise of one):

```ts
type Factory = (host: AddonHost) => ComponentType<AddonComponentProps>;

interface AddonHost {
  apiVersion: 'console-plugin-capsule/addons/v1';
  React: typeof import('react');               // the console's shared React instance
  PatternFly: typeof import('@patternfly/react-core');
  getIcon(name: string): ComponentType | undefined;   // 'pf:<name>'
  proxy: {                                    // capsule-proxy, with the user's token
    baseUrl: string;
    get(path), post(path, body), patch(path, body, contentType?), delete(path);
  };                                          // path: Kubernetes API path, e.g. '/api/v1/…'
  widget: { id; addon; baseUrl; config };
  language: string;
}

interface AddonComponentProps {
  resource: Namespace | Tenant;               // the object the page shows
  slot: 'namespace.detail' | 'tenant.row';
  compact: boolean;                           // true in table cells
  canPatch: boolean | undefined;              // undefined while checking
  patchResource(mergePatch): Promise<object>; // patches and updates the page
  refresh(): Promise<void>;                   // re-fetches and updates the page
  confirm({ title, body?, confirmLabel?, variant? }): Promise<boolean>;
}
```

Rules for modules:

- **Don't import `react` or `@patternfly/*`.** The browser can't resolve bare imports, and a
  second React copy breaks hooks. Use `host.React` and `host.PatternFly`. Write plain
  `React.createElement` (see `examples/addons/pod-count/index.js`). Or compile JSX with
  `React` as a free variable (`jsxFactory: "React.createElement"`) and bundle everything else
  into one ES module.
- Use `.js` files, so nginx serves them with a JavaScript MIME type.
- Modules come from the plugin's own origin, so the console's Content Security Policy allows
  them. Modules can't load scripts from other origins.

### Icons

These names work as `pf:<name>`: `archive`, `bell`, `bolt`, `bug`, `calendar-alt`, `camera`,
`chart-line`, `check-circle`, `clock`, `cloud`, `code-branch`, `cog`, `cube`, `database`,
`exclamation-circle`, `exclamation-triangle`, `eye`, `fire`, `flag`, `globe`, `hdd`,
`heartbeat`, `history`, `hourglass-half`, `info-circle`, `key`, `leaf`, `lock`, `lock-open`,
`network-wired`, `power-off`, `puzzle-piece`, `robot`, `rocket`, `save`, `server`,
`shield-alt`, `star`, `tag`, `times-circle`, `trash`, `user`, `users`, `wrench`.

For any other icon, ship an image (usually an SVG) in the addon and reference it by relative
path. `iconMode` sets how the plugin draws it:

- `"image"` (default): the file is shown as-is, in its own colours. Use this for multicoloured
  icons. The colours don't adapt to dark mode or to the toggle state, so the off state relies
  on the dimming and strike-through (or a dedicated `off` icon).
- `"mask"`: the file is only used as a shape, filled with the current text colour, exactly
  like the built-in icons. The icon follows light and dark mode and turns the brand colour
  when a toggle is on. Use it for monochrome SVGs; colours inside the file are ignored, only
  transparency matters.

`oc create configmap --from-file=<dir>` doesn't include subdirectories. With a ConfigMap,
keep icon files next to `manifest.json`.

## Security

- Declarative widgets (`labelToggle`, `labelValue`) contain no code. They can only read the
  page's object and patch one label on it, with the user's own permissions.
- Module addons run inside the console with the logged-in user's token, like any console
  plugin. Treat whoever can write the addon's volume source (the ConfigMap, the PVC, or the
  image) as able to act as any console user. Keep addon sources in the plugin's namespace,
  and restrict write access to that namespace.
- Paths in manifests must stay inside the addon directory. The plugin rejects `..`, absolute
  paths and URLs.

## Local development

```bash
CAPSULE_ADDONS_DIR=examples/addons yarn start
```

This command serves `examples/addons` (or your own directory, with an `index.json` and one
subdirectory per addon) at `addons/`, next to the plugin.
